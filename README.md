# Negation Scope in MaxSim-Family Scorers: code and data

Code, data, run outputs and provenance records for the article *Negation Scope in MaxSim-Family Scorers: Exact Limits,
Permutation Minimal Pairs, and the Behavior of Released Systems* (Kurban Kotan, Manisa Celal Bayar University).

Scorers that pool token-pair similarities with a maximum (late-interaction retrieval, token matching, alignment-based
inference) see a context as a bag of tokens when the token states are context-independent. The article states three
exact properties of such scorers, tests them with two diagnostics (NegPairs-Perm, permutation minimal pairs in which a
decisive and an irrelevant negation contain exactly the same words, and the nested subset of NevIR), scores 18 released
retrieval systems and three language-model judges on them, fine-tunes two late-interaction checkpoints on standard
minimal pairs, and reports a prespecified study with seven frozen encoders (718 runs).

## Data

Each `*.jsonl` item file holds one JSON object per arm: `scenario_id`, `item_id`, `arm` (O affirmative, P paraphrase, N negation
of the decisive words, S negation of an irrelevant detail), `family` (syntactic, quantifier, affixal, lexical),
`seen_family`, `domain`, `situation`, `split`, `context`, `question`, `options` (two action options), `label` (index of the correct
option), `cue`, `decisive`, and for NegPairs-Perm a `perm` record (edit sites, connector, clause order, spans).
`*_scenarios.jsonl` and `scenarios.jsonl` hold one record per scenario with the generated fields, the assembled arms
and the verification results; `build_state.json` and `build_report.json` record every candidate and every rejection.

The items were generated by Claude Sonnet 5, verified blind by Claude Haiku 4.5 and, for NegPairs-Fresh and
NegPairs-Perm, by Qwen2.5-7B-Instruct in both option orders as an acceptance condition, and audited on a 10% sample by
Claude Opus 5 (details in the article and in the manifests). They are not human-written; the human check is reported
in the article. The data are released under CC BY 4.0 (`data/LICENSE.md`).

## Reproducing the runs

Every run was made on Google Colab. Each notebook states in its first cell what it needs; Drive paths are
`MyDrive/CACSA_v3/` (manifest v3.0 and later) and `MyDrive/CACSA_v2/` (earlier manifests).

| Notebook | Run | Runtime |
|---|---|---|
| `NegPairs_v3_build_colab.ipynb` | builds NegPairs-Fresh and NegPairs-Perm (manifest v3.0) | GPU L4 (used) or A100; High-RAM not needed; a T4 does not work. `ANTHROPIC_API_KEY` in Colab Secrets; the original build cost 21.39 USD (9,269 API calls) |
| `NegPairs_v3_main_colab.ipynb` | prespecified study: pilot, 718 runs, gate, exact rules, statistical rules, NevIR, probes, Qwen audit of v1 | A100 GPU (used: NVIDIA A100-SXM4-40GB; the A100 runtime comes with High-RAM); an L4 works about twice as slowly; a T4 cannot run the Qwen audit |
| `NegPairs_v3_followup_colab.ipynb` | float64 Perm predictions of the static encoders | CPU, about 10 to 15 minutes; High-RAM not needed |
| `NegPairs_public_systems_colab.ipynb` | 18 released checkpoints on NegPairs-Perm, NegPairs-Fresh and NevIR | GPU L4 (used) or A100 (with High-RAM); on a T4 the 7B and 8B judges are skipped |
| `NegPairs_finetune_li_colab.ipynb` | ColBERTv2 and answerai-colbert-small-v1 fine-tuned on NegPairs v1 train or NevIR train, 3 seeds; SciFact check | GPU L4 (used; about 2 hours) or A100 |
| `NegPairs_build_colab.ipynb` | builds NegPairs v1 (construction v2) | CPU; `ANTHROPIC_API_KEY` in Colab Secrets |
| archived: `CACSA_v2_main_experiment_colab.ipynb`, `CACSA_v11_followup_colab.ipynb` | manifest v1.1 (CondaQA) and its follow-up | A100 (High-RAM) |
| archived: `NegPairs_build_colab_v1.ipynb`, `NegPairs_pilot_colab.ipynb`, `NegPairs_main_colab.ipynb` | first NegPairs builder, pilot and the manifest v2.0 run | CPU; A100; A100 (High-RAM not needed) |

`python make_package_zip.py` writes `cacsa2_project.zip` for the notebooks that read the package from Drive; the
released-systems and fine-tuning notebooks embed the package. API keys are read only from Colab Secrets
(`ANTHROPIC_API_KEY`; optional `HF_TOKEN`) and are never written to any output.

Third-party resources are downloaded by the notebooks at pinned revisions and are not redistributed here: NevIR
(Hugging Face `orionweller/NevIR`, revision `62635850…`), CondaQA (manifest v1.1 only, pinned commit), GloVe 6B, BEIR
SciFact (zip SHA-256 `536e1444…`), and every model checkpoint (Hugging Face Hub; the resolved revisions are recorded in
the outputs and in the article).

## Run outputs

`outputs/` holds the outputs behind every number of the article (layout, provenance and what is not included in
`outputs/README.md`). The paper pipeline reads them from there and rebuilds every number and table of the article
(`paper/README.md`). The release was checked from a fresh copy of this repository by rebuilding the number registry
(identical to the article's) and the article PDF (identical text), and by repeating the independent recomputation
(206,092 values, 0 mismatches). The release plan of the frozen manifest v3.0 named a Zenodo DOI; the release is this
repository instead.

## Tests

`python -m pytest tests` (needs PyTorch, Transformers, safetensors, spaCy with `en_core_web_sm`, scipy and
scikit-learn; the tests build tiny models and need no download beyond the spaCy model).
